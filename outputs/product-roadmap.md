# Product Roadmap — closing the "platform" gap vs competitors

> 已上线：个人画像（多步提问：学历/实习/技能/目标岗位/期望薪资/工作方式），存进工作台并跨设备同步，
> 目标岗位自带美国薪资中位数参考（`src/lib/roles.ts`）。

## 三类缺口，两种做法

| 缺口 | 能否自己做 | 现实做法 |
|---|---|---|
| 个人画像（学历/实习/技能/期望薪资） | ✅ 能 | **已做**（ProfileModal + ProfileCard） |
| 岗位介绍 / 适合岗位推荐 | ⚠️ 要数据 | 接免费岗位 API |
| 全美公司介绍 / 福利待遇 / 薪资 | ❌ 靠数据源 | 接免费政府数据 + 岗位 API，别自建 |

结论：**别自建 Glassdoor/Levels.fyi 那种公司+福利库**（那是多年数据采集）。用免费权威数据源拼出来，把自建精力留在「匹配 + 结果归因」这个别人抄不走的点。

## 可集成的免费/低成本数据源

1. **O*NET（美国劳工部，免费）**：职业定义、所需技能、典型学历、中位薪资、增长前景。适合「岗位介绍 + 推荐」。
2. **BLS OES（免费）**：按州/都会区的职业薪资分位（p10/p25/p50/p75/p90）。适合「期望薪资 vs 市场」校验，替代我们目前手写的 `roles.ts`。
3. **Adzuna API（有免费档）**：聚合美国真实岗位 + 部分薪资 + 公司名。适合「真实岗位推荐」。
4. **JSearch / RapidAPI**：备选岗位 API。
5. **公司信息**：OpenCorporates（公开注册信息）、BLS QCEW（雇主数）、YC / Workatastartup（初创公司）、Crunchbase（付费）。
6. **福利待遇**：最难。用「岗位 JD 解析 benefits 段 + 用户众包 + 精选公司库」起步，不承诺全覆盖。

## 分阶段路线

- **Phase 1（已完成）**：个人画像 + 期望薪资 + 目标岗位（手写角色薪资库）。
- **Phase 2**：把画像接进分析——匹配报告里用「你的学历/年限/期望薪资 vs 岗位」生成一条「竞争力提示」；用 BLS/O*NET 数据替换手写薪资库。
- **Phase 3**：接 Adzuna/JSearch 拉真实岗位，按「目标角色 + 行业 + 远程偏好」推荐，一键存进工作台打分。
- **Phase 4**：公司卡（简介 + 福利 + 薪资区间 + 我们的匹配分），福利用 JD 解析 + 众包起步。
- **Phase 5**：推荐引擎——「高分岗位优先投」的队列 + 投递结果回流优化推荐。

## 一句话判断

用户说的「成熟度差距」本质是**数据差距**，不是**代码差距**。我们先用免费政府数据 + 岗位 API 补数据，用「画像 → 匹配 → 投递 → 结果」这条闭环做差异化；不自建重数据的公司/福利库。
